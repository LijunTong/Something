# 更新功能的开发环境验证

更新流程要联网、要下载 100 MB 级的安装包、还要拉起 NSIS 安装器，直接手工点很难覆盖异常分支。
这里提供一条命令跑完的前两层验证，第三层（真实安装）只能手工做，原因见最后一节。

```bash
npm run build          # 首次或改了渲染层代码后执行，验证读的是 dist/
npm run verify:update  # 服务层 + 渲染层，全绿退出码 0
```

## 三层验证

| 层 | 覆盖什么 | 是否自动 |
| --- | --- | --- |
| 服务层 `scripts/headless-update-service.cjs` | `electron/services/update.cjs` 真实跑：检查更新、真下载、错误分支、白名单、安装命令 | 是 |
| 渲染层 `scripts/headless-update-ui.cjs` | 真实 Vue 页面 + 真实 Naive UI，`window.api` 换成桩：弹窗、进度、就绪、失败重试、通知与偏好 | 是 |
| 手工端到端 | 真实安装器静默安装、装完自动重开 | 否，步骤见下文 |

两层都由 `scripts/verify-update.cjs` 编排：起 `vite preview` → 起夹具 → 依次跑两个 Electron 无头脚本 → 汇总 PASS/FAIL。

## 服务层：真下载与真错误分支

`scripts/headless-update-service.cjs` 自己就是 Electron 主进程，直接 `require` 更新服务，
所以走的是和线上完全相同的代码路径（含 `.part` 临时文件、大小校验、MZ 头校验、重命名）。

覆盖的断言：

- `check()`：正常发布、404（`noRelease`）、500（`HTTP_500`）、超时
- `start()`：正常下载到 `ready`（大小一致、进度单调、无 `.part` 残留）、截断流、非 MZ 内容、声明大小与实际不符
- 白名单：`/S` 之外一律拒绝；http 只在开发期且回环地址放行；`packaged=true` 时环境变量覆盖失效
- `install()`：非打包态抛 `NOT_PACKAGED`；`installCommand()` 的参数是 `['/S', '--updated', '--force-run']`

## 渲染层：真实页面 + 桩 bridge

`scripts/headless-update-ui.cjs` 读取 `electron/preload.cjs`，把 `ipcRenderer` 换成进程内假后端，
尾部 `const api = {...}` 原样保留，因此 `window.api` 的形状与真实 preload 一致。

页面加载 `vite preview` 的地址，跑十组场景：

1. 无新版本：弹窗窄、只有「重新检查」
2. 有新版本：版本号、发布时间、安装包大小、更新日志、下载/以后再说/忽略
3. 下载中：`已下载 / 总大小 · 速度 · 剩余约 N 秒`，关掉弹窗再从「查看进度」接回（不重新下载）
4. 就绪：「立即安装并重启」「安装完成后会自动重新打开」
5. 下载失败：原因 + 重试 + 打开发布页
6. 通知：三个动作（查看详情 / 稍后提醒 / 忽略此版本），稍后提醒写入 24 小时后的时间
7. 忽略此版本：记住版本号
8. `autoCheck=false`：启动不发请求
9. 已忽略的版本：仍然静默检查，但不弹通知
10. 检查失败：给出错误与重试

桩的偏好在刷新之间用 `.data/headless/stub-state.json` 持久化，否则每个场景刷新后都会回到默认值。

## 夹具 `scripts/update-fixture.cjs`

本地假 GitHub Release，服务层与渲染层都靠它，不碰网络。

```bash
node scripts/update-fixture.cjs --port 9911 --version 9.9.9 --size 20971520
```

| 参数 | 说明 |
| --- | --- |
| `--port` | 起始端口，被占用时自动 +1，实际地址打印在 `FIXTURE_READY http://127.0.0.1:<port>` |
| `--version` | 发布版本号，默认 `9.9.9` |
| `--size` | 安装包大小（字节） |
| `--body-file` | 从文件读取更新日志 |
| `--chunk-delay` | 每个 512 KB 数据块的间隔（毫秒） |
| `--fail` | 制造故障：`500` / `404` / `hang` / `truncate` / `badmz` / `small` / `slow` |

端点：`GET /latest` 返回 GitHub release 形状；`GET /setup.exe` 流式返回安装包（首两字节固定为 `MZ`）；`GET /stats` 返回请求计数。

## 手工端到端：安装器与自动重开

这一层必须手工做，因为静默安装会覆盖本机已装的版本，自动化跑一次就可能把开发机的应用换掉。

```bash
npm run build
npx electron-builder --win nsis --publish never --config.npmRebuild=false
```

1. 在「设置 → 关于」确认当前版本号
2. 把 `package.json` 的 version 加一，重新打包出更高版本的安装包
3. 用旧版本应用检查更新、下载、点「立即安装并重启」
4. 观察：安装器静默跑完（无向导）、应用自动重新打开、版本号已是新版本

安装器命令行是 `/S --updated --force-run`：`/S` 静默安装，`--force-run` 让 NSIS 装完自动拉起应用，
`--updated` 让新进程知道自己是被更新拉起的。开发模式下 `install()` 会拒绝执行（`NOT_PACKAGED`），
所以这一层只能在打包后的应用里验。

## 为什么不能截图

本项目的 Electron 隐藏窗口上 `Page.captureScreenshot` 会稳定超时（加 `Page.enable`、`fromSurface`、
`Promise.race` 都无效），所以渲染层验证只断言 DOM 文本与元素几何尺寸，不出图。
需要看视觉时用 `npm run electron:dev` 起可见窗口手工看。

## 安全边界

- 覆盖端点的环境变量只在非打包态生效；`packaged=true` 时强制用官方地址与官方白名单
- http 只在开发期、且只允许回环地址
- 两层验证都用临时 `userData`，跑完即删；不写用户的数据库
- 夹具、桩、下载的安装包都在 `.data/` 下，已在 `.gitignore` 里
